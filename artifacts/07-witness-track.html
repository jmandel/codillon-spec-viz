07 · Witness steps on the slider — counterexamples as runs

A static counterexample is never shown as text: it is run. When the checker refutes an obligation, the solver’s witness first appears on a dashed ghost track above Codillon’s step slider, with its values in outlined shapes (a claim, not yet observed). Replay executes it with the ordinary interpreter: a genuine witness drops onto the real slider as a solid darkred ⚖ pill on its own “witness” band, next to your run; a witness that does not reproduce is struck out as spurious and the obligation falls back to unknown. Scrubbing to the pill shows the normal Codillon runtime view (arrow, values inside shapes) plus the violated predicate with the concrete values substituted — a one-level truth tree of conjunct chips, the false one underlined — and blame curves back to the instruction that wrapped or produced the bad value. A contract that fails in your own run draws exactly the same card; the pill glyph says what happened (⚖ contract, 💣 trap) and the band says whose run it was. Input witnesses are full runs; loop-head witnesses (“invariant too weak”) are a jagged one-iteration replay with a before/after pair. Use ← → to step the slider last touched.

Footer — self-critique

  • What it makes obvious. That a refutation is a fact about a run: the student gets the exact arithmetic that lied (46341 · 46341 ≤ 2147483647 → 2147488281 ≰ 2147483647, with the wrapped −2147479015 traced to line 15), scrubbable like any other run, and visibly separate from their own (band + ring + “w” step labels, R14). Static and dynamic failures share one card, so learning to read one teaches the other. The ghost → replay → (solid | spurious) pipeline makes “the solver said so” and “we observed it” different pictures, and a spurious model degrades to unknown, never to darkred (principle 3).
  • What it hides. Facts are not drawn on shapes: a proven or unknown predicate is invisible until something fails (rubric 5 is weak). The card explains that a conjunct is false on these values, not why the proof needed it; for spec bugs (S2, P3) the strongest mark still lands at the exit, with only an underline + link on the spec text. Cause–symptom gaps (hash (b): delete at w217, failure at w241) are shown only by the origin curve and the memory row, not by a mark at the delete.
  • Scaling. One ⚖ per obligation site and one pill per witness keep the gutter scannable (169-line hash table + minimap). Long witnesses compress on the slider (247 steps fit), but several witnesses would need the “shortest first, others collapsed” rule (only one per bug here; alternates are summarised in the shrunk-input card, e.g. “also 0, 1, 9, 16 · n = 5 passes”). Cards are overlays in the right margin, so row height never changes (R23); far-apart spec links become long curves.
  • Cost in Codillon. Cheap where it matters: the interpreter, slider, ticks, values-in-shapes and arrow already exist; a witness is just another execution log appended to the slider with a segment marker. New pieces: (1) solver model → concrete inputs or a loop-head state (needs “start at loop head with these locals” in the instrumented runner — about 50 lines in this prototype), (2) per-step evaluation of spec predicates on concrete values (an ℤ evaluator with spans for underlines), (3) wrap detection on add/mul (exact vs wrapped), (4) the card renderer (HTML overlay, like data-commentary). The ghost track is a second Slider component.
  • Honest caveats. Solver output is mocked: the witnesses are the fixture’s counterexamples (plus gcd(1,0) for G1, shrunk by hand, and a hand-written spurious model in A3); the runs themselves are real (embedded line-level interpreter, checked against the fixture: ). Listings use 03’s syntax verbatim (bare names, v binder) rather than 01’s $-prefixed names, so line numbers match the fixture traces exactly.
  • Deviations. The brief phrased the static/dynamic difference as “⚖ vs 💣”; I kept 💣 for traps only (R15: spec failures need their own pill), so a contract failure in your own run is a plain ⚖ pill and a witness is a ringed ⚖ pill on a witness band. Shapes widen to fit long values (e.g. −2147479015) instead of staying 30 px. Section A snippets show 5–12 lines (A1 needs the whole $half_or_neg1). Your run uses one input per program (isqrt(10), gcd(12,8), a collision-free hash sequence) so the witness is visibly the thing that finds the bug; the fixture’s multi-call runs are used only for the self-check.
