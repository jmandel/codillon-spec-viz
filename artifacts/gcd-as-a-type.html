The type of the answer never changes

This is Euclid’s algorithm with the simplest full specification there is. Its result has the type Gcd(a, b), the set of numbers whose divisors are exactly the common divisors of a and b. That set has one element. If the program type-checks, it returns the gcd and nothing else.

The proof is one sentence. A step of the loop changes the numbers but not the set of their common divisors, so it never changes the type of the answer. Here is that sentence for your inputs:

The rest of the page draws the sentence: as sets of divisors (§1), as rectangles (§2), as a program (§3), as a set of loop states (§4), as two mistakes (§5), as a machine-checked proof (§6), and as the run Codillon already shows you today (§7).

1 · The type Gcd(a, b)

Write Div(n) for the set of divisors of n. The common divisors of a and b are CD(a, b) = Div(a) ∩ Div(b). The type is the set of numbers whose divisor row is exactly that row:

Gcd(a, b) = { g ∈ ℕ | Div(g) = Div(a) ∩ Div(b) }

Each row below is a set drawn as dots on one shared number line. Move the candidate g. Its row is laid against the row of common divisors. When the two coincide dot for dot, the rule under them is solid and g inhabits the type. An extra divisor has no socket, so it spills above the row in darkred. A missing divisor leaves its socket hollow and darkred.

Lean · def Gcd

The bottom line of the figure is the whole type, drawn as a set of numbers: exactly one point is lit. That is a dependent refinement type: a set of numbers that depends on the values a and b. Move a or b and the set moves. The type is really a family of sets, one for each pair of inputs:

A value of a refined type is a value plus evidence. Lean writes the type as a subtype, { g : Nat // ∀ d, d ∣ g ↔ d ∣ a ∧ d ∣ b }, and a value of it as the pair ⟨g, proof⟩. Here you can check the evidence by eye: the two rows coincide.

At run time the evidence is erased. Only the number travels through the program (§7).

2 · Why one step keeps the divisors

Draw x and y as an x × y rectangle. A number d divides both sides exactly when a grid of d × d squares tiles the rectangle with nothing left over.

One step of Euclid cuts q = ⌊x / y⌋ squares of side y off the rectangle and leaves a y × (x mod y) rectangle. A grid that tiles the whole rectangle tiles each y-square, so it tiles what is left. Going back, x = q·y + (x mod y), so a grid that tiles the squares and the remainder tiles the whole. That is the one lemma the proof needs:

Div(y) ∩ Div(x mod y) = Div(x) ∩ Div(y)

grid side d:
Lean · step_keeps_common_divisors

Pick a d that is not a common divisor: the grid misfits on some edge, before the cut and after it. Cut to the end: the last squares are g × g. The gcd is the side of the largest square that tiles the original rectangle. Every common divisor tiles it too, and those are exactly the divisors of g.

3 · The program

Here is Euclid in Codillon’s own idiom, one instruction per line. The header says what the function returns: a $g such that, for every d from 1 to a + b, d divides $g exactly when d is a common divisor. The bound is exact: a nonzero divisor of a or b is at most max(a, b), and every d divides 0.

The loop carries a type too. Its invariant says the common divisors of ($x, $y) are those of ($a, $b), and (@decreases $y) is its termination measure. Every obligation is proven (§6 has the proof), so the listing is calm: gray line numbers, plain rules, nothing extra. The result’s refined shape on line 29 is the type as a single socket on its number line. Drag the slider or press ← / → and watch the returned value seat in it.

4 · The loop has a type

The loop’s state is the pair (x, y). The invariant is a set of states: every (x, y) whose common divisors are those of (a, b), which is every state with gcd(x, y) = gcd(a, b). It is shaded below. In other words, the shaded states are the ones where Gcd(x, y) = Gcd(a, b): the loop never changes the type of the answer.

Typing the loop takes three containments and one decreasing measure, and you can read each one off the picture.

8 · Version 2: the same proof in the real editor

Everything above is drawn by this page, and its verdicts are written by hand from the Lean proof. Refined Codillon version 2 checks the same Euclid loop in the real editor, with a small deterministic kernel and no solver. The refinements are the types, and the kernel finds the arithmetic between the facts by itself, so the file has no prove lines. Every proof it finds is still drawn: each cup states its proposition and source line beside its line, with a wire from every fact used. The spec is two Wasm functions

$gcd_ref (line 89) is Euclid written recursively, as a predicate: if b = 0 it returns a, otherwise $gcd_ref(b, a rem_u b). Because it recurses, it needs a measure, measure:gcd_ref, which is just b. The measure cup on the recursive call (line 99) is proven automatically, because a remainder is always below its divisor. Its label reads “✓ true for every value”. $is_gcd(g, a, b) (line 71) is the meaning of §1’s type Gcd(a, b), made computable. It says g divides both a and b ($common), and no common divisor lies above g up to a + b ($no_cd_above, recursive, with its own measure). Both are pure, total, loop-free functions. The editor runs them, and the kernel reasons about them.

Where each fact comes from

  • The result type of $gcd (line 107) is v = $gcd_ref(a, b).
  • The loop invariant is a block type. loop $euclid (line 116) carries $gcd_ref(x, y) = $gcd_ref(a, b), the counterpart of §4’s “the type of the answer never changes”. block $done (line 115) carries the same fact plus y = 0. Every branch out must supply both.
  • Entry (line 116). After x := a; y := b both sides are the same term, so the kernel proves the loop-entry cup with no facts at all: “needs gcd_ref(x, y) = gcd_ref(x, y) ✓ true for every value”.
  • Branch facts. local.get $y; i32.eqz; br_if $done (lines 117–119) gives the taken edge y = 0, which is exactly the block’s exit fact, found by lookup. The fall-through gets y ≠ 0, and the divisor cup of i32.rem_u on line 122 finds that fact by exact match. That is the wire from 119 to 122.
  • The step. unfold $gcd_ref $x $y (line 124) enters one step of the reference, $gcd_ref(x, y) = $gcd_ref(y, x rem_u y) when y ≠ 0. Then local.set $x and local.set $y rebind, the old facts fray, and the back-edge on line 129 must re-establish the invariant for the new x, y. The kernel does it from three facts, and its label says which: “✓ from lines 116, 119, 124”, the old invariant, the guard and the unfolding. The account states them about the new variables: the old y is now x, so the guard reads x ≠ 0, and x@116 names the old x, as it was at the loop head. This is §2’s lemma, restated about the reference function instead of about divisor sets.
  • Exit. After the block, unfold at y = 0 gives $gcd_ref(x, 0) = x (line 133), and the result cup on line 134 is proven from it and the block’s two facts: “✓ from lines 131, 133”.
  • The harness (line 135) calls $gcd, checks $is_gcd(g, a, b), and branches past unreachable. On the fall-through, lemma $gcd_ref_ok (line 146) calls the instructor axiom axiom:gcd_ref_is_gcd: if g = $gcd_ref(a, b) then $is_gcd(g, a, b). With it, the kernel derives False for the ⊥ cup on line 147, whose label ends “(assuming line 105)”, the axiom’s line. That one cup is assumed, and the other 13 are proven.

How this differs from the Lean proof and from the five-rule calculus

Against the Lean proof (§6). Lean proves the whole statement, Div(g) = Div(a) ∩ Div(b) for all natural numbers, from the core lemma Nat.dvd_mod_iff. It trusts nothing beyond Lean’s kernel and core library. Version 2 splits the work. The kernel proves, for all 2³² × 2³² unsigned inputs, that the loop computes exactly what the recursive reference computes and that rem_u never divides by zero. The number theory, that Euclid’s reference really yields a greatest common divisor, is the one axiom. The design leaves room for that axiom to be justified in Lean, but the bridge is not built (research 16 §9, Q6). Version 2 also proves partial correctness only: the loop is not proven to terminate, although $gcd_ref’s measure makes the predicate total.

Against the five-rule calculus. That page decides every premise by enumerating a 0..32 grid, so it says nothing about gcd(1071, 462), and nothing about 32-bit arithmetic. Version 2 enumerates nothing. It covers every 32-bit input by lookup, unfolding and linear arithmetic over unsigned readings, and it pays with an axiom and with two unfold lines written by hand. The arithmetic between the facts is found by the kernel, and it is drawn on the lines where it is used. Both keep the same shape: the invariant is a type on the loop, and each step is a small, checked fact. The tutorial is Refined Codillon, version 2.
