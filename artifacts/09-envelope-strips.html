09 · Envelope strips — the trajectory inside the spec band, over time

Every refined value gets a horizontal strip stacked under Codillon's step slider and sharing its x-axis (x = step, y = value). The refinement is a shaded band in the value's type colour: flat for i < CAP, moving for r·r ≤ n (its ceiling sits at √n), a staircase for a decreases measure (each arrival must land below the previous one), a rail for an equality, a punched hole for ≠ 0, allowed lanes for a three-state memory cell. The actual run is a stepped line; the slider's cursor sweeps all strips at once. The spec is enforced only at checkpoints (loop-head arrivals, call boundaries, writes to a refined local), marked as notches. A spec violation is the line outside the band at a checkpoint: a darkred dot, the crossed edge thickened and labelled with its conjunct chip, a darkred pill on the slider underneath, and ⚖ on the code line that must change. Values stay inside the type shapes, both in the code margin and on each strip's label.

Axes: strips whose values span more than a few thousand use a symmetric-log value axis (so 0…2³¹ fits next to 0…8); values that cluster far from 0 get a zoomed axis with a break mark. Strips show refined values by default; plain temporaries are listed as one-line collapsed strips (click a label to expand). Self-critique

  • What it makes obvious. When and by how much a value leaves its set, and how close it ran to the edge before it did: isqrt's r hugging the √n ceiling, the decreases staircase going below zero, the probe index of bug (d) sawing past the used ceiling forever. Moving bands make dependent refinements literal: the edge visibly is another value. Slack (a band far wider than the trajectory ever uses) and too-strong specs (S2's open ceiling exactly at the answer, G3's line starting above y ≤ x) are both pictures, not messages.
  • What it hides. Strips are per-value, so they say little about why a value went wrong (dataflow); blame comes from the gutter ⚖ on the static-failure line and from strip→code highlighting, not from the strip itself. Quantified facts (R3's "no EMPTY on any key's path", the probe-path invariant) become per-slot lane bands, which is faithful but indirect; bug (b) needs a read-link drawn from the failing $find result back to the slot-3 strip. Purely static failures with no reachable run (isqrt overflow at n ≥ 2147395600 takes 695k steps) can only be shown as a one-iteration loop-head replay.
  • How it scales. Linearly in the number of refined values: isqrt 5 strips, gcd 7, hash table 14 (8 of them three-lane slot strips). Long runs (900 steps) still fit at ~0.7 px/step; for 100k-step logs the strips would need min/max decimation and a fisheye around the cursor. The default "refined values only, temporaries collapsed, auto-expand on failure" keeps the column short.
  • Cost in Codillon. Cheap on the runtime side: Codillon already records the full step log; strips need per-step locals (already shown in shapes) plus evaluation of band edges at each step, i.e. the same predicate evaluator the dynamic checks need. The renderer is one SVG polyline per strip plus a band path, re-drawn only on edit; the slider moves a single cursor. The new obligation: each spec conjunct must be compiled into "bound as a function of state" (lo/hi/eq/set/≠), which works for interval-shaped predicates and falls back to a 0/1 truth strip for the rest.
  • Deviation. Section B shows both isqrt and gcd behind a program toggle (one program at a time keeps the page short). Section C offers all five hash-table bugs, not just (b) and (d). Syntax follows 03's listings verbatim (01's v-style refinements); traces are re-executed in a line-level JS interpreter that reproduces all 187 fixture key frames exactly, so every step number matches the fixture.
