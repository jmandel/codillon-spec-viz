01 · Shape-as-value-space — containment typing with the spill glyph

Codillon already draws an i32 as a little rectangle. Here that rectangle is taken literally: it is the i32 number line, INT_MIN at its left wall, INT_MAX at its right wall, on a piecewise scale (linear around 0, logarithmic toward the walls) so that 0, small integers and the extremes all stay legible. A refinement (i32 | P) is a region carved out of the shape: an interval between fence posts, a comb for parity, sockets for a finite set, a socket tethered to another value for a dependent bound. An input cup shows the region the instruction requires (its rim); an output shows the region the instruction provides. Subtyping is literal containment: whatever pours in must fit under the rim. When it does not, the excess spills over the rim as a darkred hatched sliver, and that sliver is exactly the set of counterexamples. The value at the current step is a dot inside the shape. Hover any shape to zoom it; click to pin.

B · Number theory: $isqrt (integer square root by linear search)

Spec: (param $n (i32 | 0 <= v)), (result (i32 | 0 <= v && v*v <= n && n < (v+1)*(v+1))); loop invariant 0 <= r && r*r <= n, measure n − r*r. The result cup on the closing line is a one-integer window tethered to n (between √n−1, open, and √n, closed). It slides when you change n. C · Hash table: 8 slots, linear probing, tombstones, ghost map M

Every memory slot is a triple of i32 cups (state, key, value). The state cup has exactly three sockets (EMPTY 0, FULL 1, TOMB 2); while a slot lies on some key's probe path, R3 removes the EMPTY socket. A FULL slot's key cup has one socket per key of M (a socket already claimed by an earlier slot is hollow: R2). Its value cup has the single socket M[key] (R1). used must sit in [0, CAP) on the socket #non-EMPTY (R4). R1 and R4's counts are only required between operations; mid-operation they are drawn as thin sockets and are not enforced.
