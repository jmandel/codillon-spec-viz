06 Model / memory mirror

A data-structure spec relates two pictures: the ghost model M (a sorted row of key↦value beads) and the concrete memory (the 8 slots of linear memory, drawn as the ring the probe index actually walks, (h(k)+d) & 7). Each bead hangs by a string to the FULL slot that holds it, and the probe arc from h(k) to that slot runs along the ring. The representation invariant R is then a geometric property of the picture: every bead has exactly one string (ii), every FULL slot is hung from a bead (i), no arc passes over an EMPTY slot (iii), and the ring keeps at least one EMPTY slot (iv). A bug is a picture that does not line up: a cut arc, a bead with no string or two, a ring with no gap. For scalar programs the model is the mathematical function, so the mirror shrinks to two beads, ⌊√n⌋ and $r, that must coincide.

Self-critique

  • What it makes obvious. Representation-invariant failures (F11/F12) become misalignments you see before you read: a cut arc (iii), a floating bead or a bead with two strings (ii), an unhung FULL slot (i), a ring with no gap (iv). Cause and symptom separate in time (bug b: the arc is cut at step 217 by delete, the lookup fails at 241), and the slider pill lands on the cause, while the code gutter's ⚖ lands on the line that must change.
  • What it hides. The mirror is a picture of one state; the universally quantified obligation (“for every table satisfying R”) is only shown by the static ⚖ on the code line. Bug (b) is subtle: R really stays true, so the picture has to draw R as line 38 reads it (TOMB = stop); that reading is a second, derived invariant the student never wrote. Instruction-level facts (parity, bounds on an index wire) are not this idea's job and stay in the fraction column.
  • Transience. R is legitimately false in the middle of an insert. The mirror draws that as an “R open” frame with gray, unpinned strings; it turns darkred only when the falsity survives to the next operation boundary (the trace is a full time-travel log, so this is known). That rule is what keeps the no-bug run calm.
  • Scale. 8 slots × 8 beads is about the limit for strings (bug d already fans 8 strings through the ring). Beyond ~16 slots it needs the ring to collapse into a row with arcs above, and beads to be filtered to the keys touched in the current operation. 100-line listings stay readable because the mirror is docked beside the listing, not in the margin.
  • Cost in Codillon. The step log already records memory; the mirror needs (1) a (@region …)/(@ghost) declaration to know where the slots are and what the model is, (2) evaluating each R clause per logged step (bounded quantifiers over 8 slots: cheap), and (3) an SVG component with keyed beads/cards so the existing 0.25 s tweens animate changes. The layout (ring vs. row) must be declared or inferred from the & (CAP-1) mask, which is the hard, unsolved part for arbitrary structures.
  • Syntax and data. isqrt uses 03's listing and fixture traces with 01's $-prefixed spec syntax; the hash table keeps 03's listing verbatim. Traces for the no-bug runs, the earlier operations of (b′), (c), (d), and the (b) cascade (insert(11,111)) were regenerated with the fixture's own reference interpreter (marked “derived” on the slider); the fixture frames are embedded unchanged.
