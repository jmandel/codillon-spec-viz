## Blocking issues (kept current)

**B3 — panic on an empty `br_table` (kernel.rs:1480, `ls.len() - 1`).** The parser accepts `br_table` with no labels (`Ins::BrTable(vec![])`); `control()` computes `let n = ls.len() - 1;` and panics with an arithmetic underflow (debug) or wraps to `usize::MAX` (release, then `j < n` for every label, and the default edge is never produced). A half-typed `br_table` line in the editor takes the whole kernel down. Reproducer: `adv/m5-brtable.wat` (`PANIC in check_module` in `adv-results/m5-brtable.txt`). Fix: reject at parse time (`br_table` needs at least one label) and guard in `control()`.

**B4 — SOUNDNESS (termination): a recursive predicate whose `measure:` has no value result gets no measure cup.** `measure_cup` builds the cup with `call_term(mf, …)`, which returns `None` when the measure function has no result, and the `?` silently drops the cup. `predicate_checks` verifies the measure is pure, loop-free and non-recursive but not that it returns `i32`/`i64` with `$f`'s parameters (R31). Reproducer: `adv/more.wat` `$p_m1` (recurses on `n + 1`, measure `(func $p_m1_m (export "measure:p_m1") (param $n i32) nop)`): output shows `$p_m1 verified=true strict_clean=true` and no `Measure` cup. The same `?` drops the cup when the measure's arity does not match (`call_term` still succeeds there, so it is only the no-result case). Fix: on the measure's header, require exactly one `i32`/`i64` result and the same value-parameter list as `$f`; if the cup cannot be built, emit a line error on the call site.

**B5 — SOUNDNESS (narrow): the virtual `rem_u` guard does not cover the result's range (solver.rs `tr_op`, `RemU` non-constant).** For a non-constant divisor the result variable is created with `hi = a.hi.min(b.hi − 1).max(0)` *before* the `B = 0 ∨ r + 1 ≤ B` split, so in the `B = 0` branch `r` is still bounded by `b.hi − 1` (and by `r ≤ A`), although §3.2 says a virtual division by zero is an unconstrained value. When the divisor's interval is `[0, 0]` or `[0, 1]`, `r` collapses to 0 and anything about it is provable. Found by the second fuzz batch (`fuzz/cases2/0218.wat`): with `x < 16`, goal `(i32.lt_s (i32.rem_u $x (i32.div_u $x 16)) 84)` is **Valid** although `x/16 = 0` for every admissible `x`; the brute-force oracle says false (trap) and the spec's semantics says unprovable. Fix: compute `hi` from `a.hi` alone unless the term is real or `b.lo > 0`, and apply `r ≤ A` only under the same guard (in the `B = 0` branch the leaf should be free in `[0, 2ʷ)`). Related spec question for the coordinator: §1.3 says `(fact E)` means "E evaluates to nonzero", which makes a trapping `E` *false*, while §3.2 makes a virtual division by zero *unconstrained*; R35's runtime check of such a fact would trap rather than report "check failed". Either is defensible; the spec should say which, and the fuzz oracle follows the first.

**Resolved.** B1 (hang on `x·y`, fixed in 4ab6743: canonical `Lin`, bounded elimination loop, regression test) and B2 (sign error in `le0`, fixed in 8715c8d; isqrt's bogus countermodel `u(n)=131071, u(r)=65535` at line 35 disappeared with it, and the oracle went from 195 to 201). Both re-verified on the snapshot: fuzz 0/300 unsound; `adv/wrap.wat` `$w3` now fails with `u($x)=0`.

**B1 (fixed) — `prove` hangs forever on any product of two non-constant terms (solver.rs `poly_mul` + `omega`).** `poly_mul` builds `Lin { ts: a.ts.map(|(v,c)| (v, c·b.c)) }`; when the other factor's constant part `b.c` is 0 (the normal case: `x·y` where both are plain variables) this inserts terms with **coefficient 0**, breaking `Lin`'s "no zero coefficients" invariant (`plus` only drops a zero when both sides mention the variable). In `omega`, the zero-coefficient variable is collected into `vars`, has 0 lower × 0 upper bound pairs, so it is chosen for elimination first, but `partition(coef(v) < 0 / > 0)` leaves every constraint in `keep`, so nothing changes and the `loop` never terminates. Found by fuzzing (case `fuzz/cases/0170.wat`, goal `(i32.lt_u (i32.shr_u (i32.mul $x $y) 1) (i32.add (i32.div_u $x 16) $y))`, hyps `x < 16, y < 16`); traced with instrumentation in the snapshot: every FM round prints the same 9 constraints, one of them `[(0, 0), (2, -1), (3, 2)] + 0 ≤ 0`, eliminating `v0` each time. Minimal reproducer: hypotheses `u(x) < 16, u(y) < 16`, goal `(i32.le_u (i32.mul $x $y) 225)` (any goal where `x·y` survives to Omega). Impact: the kernel runs on every keystroke; one such `prove` freezes the editor, and the isqrt examples (`r·r`, `(r+1)·(r+1)`) go through this path. Fix: normalize `Lin` construction (drop zero coefficients in `poly_mul`, or make `Lin::plus`/a constructor canonicalize), and add a defensive guard in `omega` (a chosen variable with no bounds must still be removed from `vars`; bound the loop by the number of variables).

**B2 (fixed) — SOUNDNESS: sign error in `le0`'s lower-bound tightening makes the solver prove `x − 1 < x` (and every wrapping subtraction) with no hypotheses (solver.rs `le0`).** For a single-variable constraint `k·x + c ≤ 0` with `k < 0` the code sets `var.lo = max(var.lo, −fdiv(c, −k))`; the correct bound is `x ≥ ⌈c / (−k)⌉`, i.e. `−fdiv(−c, −k)`. The sign is flipped, so `−x − 3 ≤ 0` (which means `x ≥ −3`, vacuous) tightens to `x ≥ 3`. This fires inside `wrap()`'s result-range constraint `0 ≤ exact − 2ʷq`: in the wrapping branch of `sub(x, c)` (q = −1), `−(x − c + 2³²) ≤ 0` becomes `x ≥ 2³² − c`, which makes the variable's interval empty, so the wrapping case is pruned as "infeasible" and the proof goes through. Confirmed on the snapshot: with hypotheses `u(x) < 16, u(y) < 16` the solver returns **Valid** for `(i32.lt_u (i32.sub $x 1) $x)` and for `(i32.lt_u (i32.sub $x 3) $x)` (false at x = 0, resp. x < 3), and fuzz case `0195` (`ge_s(mul(sub(y,1),1), shr_u(shr_s(y,2),1))`, false at y = 0) is also "Valid"; trace shows `T(1)[4294967295,15]` (lo > hi) after the tighten. Reproducers: `fuzz/one/w0.wat`, `w2.wat`, `fuzz/cases/0195.wat`; as a program, `adv/wrap.wat` `$w3` (expected: prove fails). Because the prepass records these intervals in `bounds`, the wrong bound also poisons every other case of the same `prove`. Fix: `var.lo = var.lo.max(-fdiv(-l.c, -k))` (ceiling of `c/(−k)`), and add `debug_assert!(var.lo <= var.hi || …)` plus a regression test with `x − 1 < x`. The decision-procedure fuzz (`fuzz/`) should be adopted as a kernel test: it found both B1 and B2 in 300 cases.

## Non-blocking findings (kept current)

Ordered by importance.

- **N1 — the oracle test cannot fail.** `tests::oracle_report` computes `ok/n` per example, prints a report and writes `target/v2-oracle-report.txt`, but asserts nothing; `cargo test` is green at 195/201 and at 201/201 alike. `compare()` also does not count `EXTRA` cups (cups the kernel reports that the oracle does not list) against the score; HEAD has three (`gcd*.wat` line 131, a `BlockFact` fed by dead code on the `end` after a `br`). Make the test assert `ok == n` and no `EXTRA`/`MISSING`, or list the dead-code `end` cups in the oracle (they are legitimate per R22, so the oracle should probably gain them). Also adopt the decision-procedure fuzz (`kernel-review/fuzz/`) as a test; it found B1 and B2.
- **N2 — `verified` ignores predicates and measures used in propositions (§6.1 fidelity).** `check_module`'s fixpoint only follows `call` and `lemma` edges. `adv/more.wat` `$m7` has a refinement `$p_div` whose body divides by its argument with an unfed cup; `$p_div` is `strict_clean=false` but `$m7` is `verified=true`. §6.1 requires "every predicate, measure and lemma they use" to be proven. Fix: add the predicates named in the function's propositions (header, locals, block types, `unfold`/`lemma` args) and their measures to the callee set.
- **N3 — mutual recursion between predicates escapes R29.** `FnInfo::self_rec` is direct recursion only; `adv/more.wat` `$even2`/`$odd2` are accepted without a measure and marked verified. No hang (the solver's `UNFOLD_DEPTH = 4` and the evaluator's budget bound everything), and no trap-freedom consequence, but a non-terminating spec is accepted silently. Fix: compute recursion over the call graph's SCCs; any predicate in a nontrivial SCC needs a measure (or is rejected, since R29 allows only direct self-recursion).
- **N4 — `assume` inside a predicate is accepted (R34).** `adv/more.wat` `$p_assume` is `verified=true`. A `prove` in a predicate body can use the assumed fact to discharge a trap cup, so the predicate looks total but traps in evaluation. One-line check in `step` (`self.ghost && is_pred ⇒ error`).
- **N5 — `gradual` is plumbed but unused** (`let _ = cx.gradual;`). Strict and gradual produce identical outputs; unfed cups are `RuntimeChecked` in both modes, and in strict mode no `strict_error` is produced. The oracle's `verdict` strings happen to be mode-independent, so the tests cannot see this. Fine for now (the status file says runtime checks are the next step), but §4.1's "strict mode reports unfed cups as errors" is not yet true at the API.
- **N6 — pure i32 helper functions used as `if` conditions become predicates.** `mk_eq`/`atom_of` turn any i32-valued call into a `Bool` atom and `info.rs` marks every function named in a branch fact as a predicate, so an ordinary helper used in a condition is subject to R29 purity errors on its header. Consistent with the letter of §1.7, but worth a gentler message ("`$f` is used as a condition at line N; it must be pure…").
- **N7 — handle message.** `local.get $h` on a handle set inside an inner arm reports "`$h` holds no fact" (handles are restored at frame exit) where §1.5 says "holds a fact that ended at line N". Same outcome (error, cup unfed); the message loses the line.
- **N8 — evaluator panics on malformed input** (from the previous range, still present): `st.len() - bt.params.len()` and `st[st.len() - c.arity..]` underflow on a shallow stack; reachable only through a predicate body that `wat` would reject, but the kernel runs before `wat`.
- **N9 — `symex` refuses `return`/`br_if` inside predicates**, so such predicates stay opaque to §3 (R29 promises `ite` for them). Sound; the oracle examples do not need it.
- N10 — F3–F6 from the parser range (tokenizer unification done; `to_bits` silently reduces out-of-range literals; roles only from inline exports) remain as noted below.

**F1 (fidelity, erasure, spec gap shared with `erase.py`).** §1.5 says a fact *parameter* `(param $h (fact P))` is a handle, and §1.8 says `local.get/set/tee` of a fact local erase to `nop`. `erase_lines` only records `(local $h fact)` declarations in `fact_locals`; a `local.get $inv` where `$inv` is a fact parameter would be left as a real `local.get` of a parameter that the header erasure has deleted, so the erased module would not assemble (unknown local) or, with numeric indices, silently read a different local. Instruction names such as `f32.convert_x`, `i32.trunc_`, `i32.trunc_sat_f` (fewer than 3 bytes left, or a non-ASCII char boundary) panic instead of returning `Err`. Since the kernel is meant to re-check on every keystroke in an editor, a half-typed instruction name is the normal case, not an edge case. Reproducer: `Module::parse("(func $f\ni32.trunc_\n)")`.

**F3 (fidelity, minor).** `erase::split_comment_py` finds `;;` with a plain `find`, not string-aware (a `(export "a;;b")` would be cut); `sexpr::split_comment` is string-aware. The two disagree on such lines, so the parser and the eraser can see different code. Cosmetic until export names matter for roles, which they do (`lemma:`/`axiom:`/`harness:`).

**F4 (fidelity, minor).** `erase_groups_chars` recognizes `(T | …)` only when `|` is followed by whitespace-separated tokens such that `toks[1].starts_with('|')`; `(i32 |$p)` works but `(i32| $p)` does not (tokenized as `i32|`). The s-expression reader tokenizes `|` as its own token in all cases, so again parser and eraser disagree on the same text. Pick one tokenizer for both.

**F5 (fidelity, note).** `to_bits(I32, v)` silently reduces out-of-range literals (`i32.const 4294967296` becomes 0) where `wat` rejects them; `parse_memarg` turns a negative `offset=` into a huge `u64`. Low priority.

**F6 (design note, roles).** Roles (`lemma:`, `axiom:`, `harness:`, `measure:`) are read only from inline `(export …)` in the header. A separate `(export "axiom:x" (func $f))` line is `LineKind::Other` and ignored, so such a function would be checked as an ordinary function with an empty body. That is the conservative direction (nothing is trusted that was not declared inline), so this is fine; worth a one-line error rather than silence.

### bb91d7b, c938a33 — shared tokenizer, fact-param handles, no-panic parsing; term/eval/info/symex/solver/out land

F1–F4 of the previous range are addressed (fact params are now collected as handles by `erase::fact_params`; the eraser uses `tokenize_spans`; `parse_float_op` uses `get(..3)?`; a `malformed_lines_never_panic` test covers the cases I listed). 8 tests pass in the snapshot. `kernel.rs` is in the commit but contains only the pass scaffolding (terms, lane, lookup, evaluation); the per-instruction pass is not committed yet, so **no cup verdict is produced by HEAD** and the oracle tests are not wired. This range is reviewed as: term model (R1–R4), module pre-scans (`info.rs`), symbolic unfolding (`symex.rs`), evaluator (`eval.rs`), and the decision procedure (`solver.rs`).

**Term model (`term.rs`).** `Key::{Const, Leaf, Op, Float, Call(f,args,epoch), Load(..,addr,epoch), Ite}` interned in one table; leaves are never interned (fresh). R4 normalization in `atom_of`/`mk_eq`/`negate` matches the card: `gt→lt`, `ge→le`, `eqz→eq(x,0)`, `eq(x,0)`/`ne(x,0)` on a comparison or i32 call collapse to the atom or its negation, `eq`/`ne` operands sorted by `(is_const, id)` so constants come last. `Atom::Cmp` carries no width, but both operands are typed terms, so a match implies equal width. `negate` panics on `Atom::Or` (R25's disjunction); the solver negates the goal through `assert(_, false)` rather than `negate`, so this is currently unreachable, but it is a latent panic if a future caller negates a `DivOverflow` cup. Note for later: `Key::Call` becomes a `Bool` atom for *any* i32-valued pure call used as a condition, not only for declared predicates; consistent with "a function named in a proposition is a predicate" since a branch fact is a proposition, but it means an ordinary i32 helper used in an `if` is silently subject to R29 purity errors.

**Pre-scans (`info.rs`).** Purity follows my design-review fix (a): reading a mutable global makes a function impure (`impure = "reads a mutable global"`), so A1 cannot arise through `Pred` atoms; the evaluator also refuses mutable globals. Impurity and `reads_mem` propagate transitively through `calls` to a fixpoint. `memory.size` counts as a memory read (so a predicate using it is epoch-keyed; conservative, fine). Only *direct* self-recursion is detected (`self_rec`); mutual recursion between two predicates is not flagged, which matters for R29's "recursive without measure" error and for `symex` (which does not recurse itself) — but the solver caps unfolding at `UNFOLD_DEPTH = 4` so this cannot loop. A `measure:` whose target does not exist is silently ignored.

**Unfolding (`symex.rs`).** Straight-line code, `if`/`else` (as `Ite` over the raw condition term), `select`, loads (epoch-keyed), immutable globals and nested calls. `return`, `br`, `br_if` and blocks with branches make `symex` return `None`, so the predicate stays an opaque atom. Sound (an opaque atom is weaker), but it is less than R29 promises ("`if`/`br_if`/`return` to `ite` terms"); whether the oracle examples need `return` inside predicates will show when the tests are wired. Loops and impure callees are refused. Locals not passed as arguments start at the typed zero constant — correct for Wasm.

**Evaluator (`eval.rs`).** Integer semantics checked op by op against Wasm: `div_s` traps on `MIN/-1`, `rem_s` by `-1` is 0, shift counts mod width, rotations, sign extensions, `wrap`; results masked to the result width. Budget 100,000 steps plus a call-depth cap of 2000 (reported as `Budget`, so deterministic). Mutable `global.get` is `Unsupported`, stores and other impure ops are `Unsupported`. Malformed-input panics remain: `st.len() - bt.params.len()` underflows for a block with params on a shallow stack, `st[st.len() - c.arity..]` likewise, and `br_table` with no targets hits `ls.last().unwrap()` (the parser accepts `br_table` with zero atoms). The evaluator runs only on predicate bodies and harnesses, which Codillon has already type-checked in practice, but the kernel re-checks on every keystroke, so a half-edited predicate can reach it.

**Decision procedure (`solver.rs`).** Architecture differs from §3.3–3.4 in a way that is still deterministic: there is no separate interval pre-pass followed by case enumeration by splitting-term id; instead `prove` does (i) two `prepass` rounds that translate the hypotheses and the negated goal with splitting *disabled* (the first split aborts the atom) and record single-variable bounds per opaque term, then (ii) a depth-first enumeration over a `choices: Vec<bool>` replay vector, where every split point (`wrap` carry, `ne`, `ite`, comparison-as-value, `signed` sign, `rem_u` guard, `Or`) consumes one choice, re-translating from scratch per case (`reset_run`). Early exit on `Infeasible` prunes the subtree. Enumeration order is the textual order of translation rather than "by id of the splitting term" (§3.4); both are deterministic for a fixed input. Checked correct on reading:

- Add/Sub wrap resolution by interval (`q0 == q1`), else a `[0,1]` split with the result-range constraint `0 ≤ T ≤ 2ʷ−1` (the "`eq(add(x,0),x)` with q=1" pitfall is covered).
- `mul`/`shl` by constant: `k·A − 2ʷ·q`, `q ∈ [⌊k·lo/2ʷ⌋, ⌊k·hi/2ʷ⌋]`; constant 0 collapses. Non-constant `mul`: polynomial expansion only when neither factor carries a wrap/monomial variable, else a `TermMono` leaf; retry per case happens naturally because each case re-translates.
- `div_u`/`shr_u`/`rem_u`/`and`-mask by constant `c ≥ 1`: `c·d ≤ A ≤ c·d + c − 1`; `c = 0` is an opaque leaf (A4 residue fixed); `and` with mask `2ᵏ−1` only when the mask is of that form (`(m+1)&m == 0`, including `m = 0`).
- Non-constant `rem_u`: `r ≤ A` and `r + 1 ≤ B` only if the term is **real** (`Env::is_real`) or `B.lo > 0`; otherwise a case split `B = 0 ∨ r + 1 ≤ B` (A4 fixed, *provided the kernel's `real` set is maintained correctly*; see watch items). Non-constant `div_u`: only `r ≤ A`, as §3.2 says.
- Signed readings: `σ` resolved by interval or split; `extend_i32_s`, `shr_s` by constant per the table; `shr_s` by 0 is the identity.
- Comparisons as values and `ite` are two-way splits; `and` of two comparisons is handled propositionally (both true / split on the negation).
- Omega-lite: equalities solved on a ±1 variable (lowest-numbered by `ts` order), gcd test otherwise; tighten by gcd with floor; parallel constraints deduplicated keeping the tighter; FM eliminates the variable with fewest lower×upper pairs; the exactness condition is `a == 1 || b == 1` per pair, which is the correct real-shadow = dark-shadow condition; an inexact but satisfiable case yields `Inexact`, an inexact-unsat case is correctly treated as unsat. Caps: 64 terms per atom, 24 variables (counted over variables actually used), 256 cases, 256 constraints after tightening, i128 overflow → `Cap("coefficients…")`.

**Watch items for the pass code (potential soundness, cannot be decided from this range):**

- **W-a: `Solver.bounds` is never cleared.** `prepass` accumulates per-term bounds in `self.bounds` and `prove` does not reset it. If the kernel reuses one `Solver` across `prove` lines (or across functions), bounds learned from an earlier `prove`'s hypotheses leak into later proofs — unsound. Safe only if the kernel constructs a fresh `Solver` for every `prove`. Must check when the pass lands.
- **W-b: scope of `real`.** `Pass::mark_real`/`cut_real` exist, but the pass code that calls them is not committed. A `rem_u(n,y)` computed as a real slot inside a then-arm (where `y ≠ 0`) must stop being "real" at the join, or a later virtual `rem_u(n,y)` on the merged path would get the unconditional `r + 1 ≤ B` and reintroduce A4 through the back door.
- **W-c: `tr()`'s coefficient-overflow fallback** replaces a term by an opaque variable but keeps the constraints already pushed during the partial translation. Those constraints are definitional and remain true, so this is sound; noted because it is easy to break.

**Fuzzing** (`kernel-review/fuzz/`): 300 random goals over `x, y < 16` with wrap-provoking constants, brute-forced over all 256 inputs, run against `Solver::prove` through a reviewer-only test module installed in the snapshot (`review_fuzz.rs`). Results are below once the run finishes; note the generator treats a trapping goal (`div_u`/`rem_u` by a zero divisor inside a virtual term) as "false for that input", which is stricter than §3.2's chosen semantics (a virtual division by zero is an unconstrained value), so those mismatches are classified separately.

### 4ab6743, 8715c8d — the pass (R1–R35), joins, oracle harness; B1/B2 fixes

`kernel.rs` grows to ~1830 lines: `Pass` with `step()` per instruction, `feed()` (R5 order: dead-code, lookup, evaluation, pending `prove`s, then unfed), `branch()`/`join()`/`loop_head()` for R16–R22, `do_call` (R13), `lemma_line`/`unfold_line` (R30, R33), `closure()`/`finish()` for §4.1 verdicts, `check_module` (lemmas first in callee order; `verified` as a greatest fixed point over `call`/`lemma` edges). 20 tests pass; oracle 201/201 (every cup's line, kind, operand, verdict, feed kind, feed line, `depends_on_checks`, and prove hypothesis lines agree).

**What I checked and found correct (by reading and by the adversarial programs):**

- *Lane scoping and staleness (R5–R8).* Facts are about ids; `local.set` rebinds `cur` only; joins intersect the lanes of all incoming edges by atom equality and allocate φ leaves for locals, globals and block results that differ; loop heads φ-rename every local assigned anywhere in the body (syntactic pre-scan to the matching `end`), every global set in the body, and all mutable globals if the body has an impure call (A2 fixed). Refined locals/globals/loop params re-enter `R[v := φ]` with a dependency `Group` that collects every set/edge cup, so assumption and check provenance propagate through all edges, not just the incoming ones (conservative). `adv/stale.wat` S1–S5 all unfed; S3c (if-eqz-return) proven by lookup; `adv/control.wat` C3 (br_if edge fact vs. join intersection) unfed; C9 (φ of an `if` result) unfed.
- *Epochs (R10–R13).* Stores, `memory.fill/copy/grow`, impure calls and `call_indirect` bump `ε`; loads and memory-reading pure calls are keyed by `ε`; joins take a fresh epoch when edges differ; loop heads take a fresh epoch when the body may bump it. `adv/epoch.wat` E1–E7: predicate facts die across a store (E1), an impure call (E2) and a storing loop (E6); two loads around a store are different ids (E3) and the same id without one (E4); impure call results are fresh leaves (E5); bounds `K = 65536 − o − N` (E7). A1 is closed by purity: a predicate reading a mutable global is an error, and `eval` refuses mutable globals.
- *Edge cups (R19–R21, R32).* `branch()` records the edge snapshot as `lane[mark..] + ⟦c⟧ + prove outputs`, and `feed()` returns prove outputs to the caller instead of entering them, so a `prove` feeding a `br_if` cup never reaches the fall-through lane (A3 fixed; `adv/a3-brif-leak.wat` unfed, and `adv/wrap.wat` W2/W4/W11 show the edge cup unfed while the `br` cup is proven). `br_table` gives `eq(i, j)` per listed edge and `n ≤ i` on the default (C4).
- *Trust (R33–R34, §4.1).* Axiom results are `assumed` with the axiom's origin (T1); a lemma whose body has an error makes its callers' facts assumed with the lemma's header as origin (T2, via `lemma_assumes` and `Dep::Assume(header, false)`); `assume` produces assumed facts and `prove` from an assumed hypothesis stays assumed (T7, M9); the most recent matching fact wins, so a proven branch fact above an `assume` yields proven (M8). Imported callees' results are assumed. `prove` feeds the first *unfed* cup, so it correctly reaches a `div_s`'s `DivOverflow` cup when `DivByZero` was fed by lookup (M4).
- *Dead code (R22, R26).* `go_dead` enters `False`; a loop `end` after an unconditional back-edge stays dead (C1); dead code adds no edges, so `if … return end` keeps `¬c` after `end` (S3c).
- *Evaluation (R28).* Constant cups are proven or **refuted** by the interpreter (`i32.const 0` divisor → "⟨0 ≠ 0⟩ is false (evaluated)", T8; `local.set $k` of 9 into `(i32 | v < 8)` refuted, C8); refined-local initial value (`LocalInit`) is evaluated (C8); entry values are used for result refinements even after a param is reassigned (C7).
- *Measures (R31).* The measure cup `μ(a′) < μ(p)` (unsigned) is produced at recursive `call`/`lemma` sites and is unfed for a non-decreasing measure (T4), except for B4.
- *Wraparound in `prove` (§3).* `adv/wrap.wat` W1–W12: `i+1 > i`, `x−1 < x`, `2x ≥ x`, signed `x < x+1` all fail with the right countermodels (`0xffffffff`, `0`, `0x80000000`, `0x7fffffff`); `i+1 ≤ n` from `i < n`, `x−1 < x` from `x ≠ 0`, `x ≤ x<<1` from `x ≤ 0x7fffffff`, `(x&7) < 8`, `x>>1 ≤ x`, i64 `ext_u(x)+1 > ext_u(x)` and real-slot `rem_u(x,y) < y` are proven; `div_u(x, 0) = 5` fails (constant-0 divisor is opaque, A4 residue fixed); the virtual `rem_u` guard works (`adv/a4-virtual-rem.wat`).

**Fidelity notes on this range** (beyond the blocking and non-blocking lists above): refined *parameters* are treated exactly like refined locals (cup on `local.set`, re-entered at joins) — stricter than R7, sound (M3 refuted); the `end` of a block reached only through a `br` gets a dead-fed `BlockFact` cup for the fall-through (the three `EXTRA` cups of N1); `Solver` is constructed fresh per `prove`, so the `bounds` map cannot leak between proofs (W-a closed); `real` marks are cut at `else`/`end` via `restore_to`, so a `rem_u` computed in one arm is not "real" after the join (W-b closed); `lemma_assumes` is `None` for a lemma in a cycle not yet checked, which maps to assumed (safe). Timing: each oracle example checks in 2–30 ms in a debug build; the slowest fuzz `prove` is under 1 ms.
